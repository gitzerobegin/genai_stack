Earn trust in the pull request
The buyer's stack expects
The coding agent must
L1
Models
The customer's chosen vendor and tier, pinned
Keep prompts and tools model-agnostic; qualify per task type
L2
Inference
The customer's endpoint or private route
Use a configurable client; tolerate throttling in background work
L3
Orchestration
Plan, change, test, pull request
Run durable tasks with a step budget; stop on request
L4
Tools
Tools behind the customer's tool gateway
Use allow-listed tools; run code only in a sandbox, egress denied
L5
Memory
Nothing held by the vendor
Propose learnings as pull requests to repository guidance
L6
Stores
The repository is the store
Build a per-task index; destroy it at task end
L7
Retrieval opt.
The customer's embedding service, if any
Use pinned, self-hostable embeddings
L8
Ingestion
Approved sources only
Read only what the task names; treat repository text as data
L9
Evaluation
Spans to the customer's collector
Emit agent and tool spans, pinned version, content off
C1
Gateway
Gateway-routed calls, a key per task type
Take a configurable base address; no direct vendor path
C2
Guardrails
The customer's tests, linters and code scanning
Treat the customer's CI result as the gate
C3
Privacy
The customer's privacy service
Redact personal data and secrets before any export
C4
Identity
Sign-on and provisioning; the agent acts for the engineer
Register as an agent; short-lived tokens scoped to one repository
C5
Configuration
Configuration as code in its source control
Keep policy, routes and tools in one versioned file
C6
FinOps
Cost per customer, team and task
Export tokens, cache hits and runner minutes per task
C7
Security
The customer's vault and package mirror
Resolve from the mirror only; a component list per release
C8
Governance
An evidence record per agent action
Write task, model, tools, commands, diff and approver to its store
