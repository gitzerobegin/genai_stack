# L2 reference architecture: three serving routes behind one gateway
Caption: Applications reach models through one gateway that governs three routes: managed access, a router for non-confidential traffic, and a private route through an optional optimisation layer and a serving engine to own or private-cloud GPUs, with L1 model weights beneath every route.

```mermaid
flowchart TD
  classDef note fill:#FBF4E4,stroke:#D4A13A,stroke-dasharray:4 3;
  APP["Applications / L3 workflows"]
  GW["C1 AI traffic gateway <br/>(control plane)<br/>route policy · region pin · fallback list · budgets · guards · logs"]
  APP -- "one endpoint, workload identity (C4)" --> GW

  GW -- "(A) managed access" --> A["Hyperscaler model service<br/>(Bedrock geo profile, Foundry Data Zone, Vertex regional)<br/>or inference cloud dedicated endpoint<br/>(Fireworks BYOC, Together EU dedicated)"]
  A --> AG["Provider GPUs in approved region"]

  GW -- "(B) router (non-confidential)" --> B["OpenRouter / HF Inference Providers"]
  B --> BP["Many providers<br/>(processing location per provider)"]

  GW -- "(C) private route" --> OPT
  OPT["Optimisation / orchestration (optional)<br/>llm-d or Dynamo: KV-aware routing, PD split,<br/>KV tiering, SLO autoscaling"]
  OPT --> ENG["Serving engine: vLLM / SGLang"]
  ENG --> OWN["Own / private-cloud GPUs"]

  W["L1 model weights below every route"]:::note
  AG -.- W
  BP -.- W
  OWN -.- W
```
