# L6 decision tree: whether a dedicated vector database is needed, and which
Caption: Start from the database or search platform you already operate, move to a dedicated engine only when a load test on your own data evidences a trigger, then choose that engine by where it must run and check it before go-live.

```mermaid
flowchart TD
  classDef note fill:#FBF4E4,stroke:#D4A13A,stroke-dasharray:4 3;
  classDef step fill:#0B1B33,stroke:#0B1B33,color:#FFFFFF;
  S0["<b>STEP 0 [Rec]: Non-negotiables, whatever the store</b><br/>• Source of truth for approved content lives in L8/C3, not in the store.<br/>• Entitlements from C4 are applied as filters INSIDE the search; no unfiltered fallback.<br/>• Every chunk carries doc_id, version, tenant ids, classification, region, retention_until and embed_model_version; raw text (or pointer) kept.<br/>• Rebuild-from-source is tested twice a year; it is the primary backup and exit route."]:::note
  S0 --> H1["STEP 1 [Rec]: Do you need a dedicated vector database at all?"]:::step
  H1 --> Q1{"Content already in, or<br/>naturally owned by,<br/>an operated database or<br/>search platform?"}
  Q1 --> O1["<b>PostgreSQL is a firm standard</b><br/>→ pgvector on the managed PostgreSQL service (UK/EU region), entitlement tables joined in SQL; track host pgvector version vs CVEs"]
  Q1 --> O2["<b>Elastic (or OpenSearch) is an operated platform, or the corpus is lexical-heavy</b> (ISINs, tickers, fund codes, share-class names)<br/>→ Elasticsearch hybrid (BM25 + vectors, RRF) with document-level security (OpenSearch if licence policy requires Apache-2.0)"]
  Q1 -- "none of these" --> H2["STEP 2 [Rec]: Which trigger makes a dedicated engine necessary?"]:::step
  Q1 --> O3["<b>MongoDB is the system of record for these documents</b><br/>→ MongoDB Vector Search on dedicated Search Nodes (CMK), Voyage features off until GA and Geography-scoped"]
  Q1 --> O4["<b>AWS-centred, Bedrock Knowledge Bases, large or rarely queried corpus</b><br/>→ S3 Vectors as the cost tier; OpenSearch in front if hybrid or low latency is needed; CloudTrail data events on"]
  H4["STEP 4 [Rec]: Prototypes and harnesses"]:::step --> P4{"Notebook, evaluation<br/>harness, single-user tool,<br/>non-confidential data?"}
  P4 -- "yes" --> O11["Chroma (embedded) or pgvector in a local container. Never promoted to production without returning to STEP 1."]
  O1 ~~~ H4
  H2 --> T2["(a) filtered p95 latency or filtered recall fails the budget in the existing platform<br/>(b) tenants must be isolated at scale (hundreds or more clients/funds with separate keys, quotas or deletion), beyond what schemas or indexes can manage cleanly<br/>(c) corpus size or write rate makes the existing platform's RAM or ops cost disproportionate"]
  T2 --> Q2{"At least one evidenced<br/>in a load test on<br/>your own data?"}
  Q2 -- "no trigger" --> O5["Stay in STEP 1"]
  Q2 -- "yes" --> H3["STEP 3 [Rec]: Dedicated engine, by where it must run"]:::step
  H3 --> Q3{"Must run in your own<br/>estate or air-gapped?"}
  Q3 -- "yes" --> O6["Qdrant (self-host or Private Cloud; collection-scoped JWT keys) or Milvus (Standalone/Distributed; LF AI & Data governance) for very large corpora"]
  Q3 -- "no" --> Q4{"Data plane must be in<br/>your cloud account<br/>(BYOC)?"}
  Q4 -- "yes" --> O7["<b>Open-source engine preferred</b> (exit by self-hosting)<br/>→ Qdrant Hybrid Cloud, or Zilliz Cloud BYOC (Milvus)"]
  Q4 -- "yes" --> O8["<b>Managed, proprietary, strongest control set</b><br/>→ Pinecone Enterprise BYOC (Dedicated Read Nodes only; Nexus is a separate decision)"]
  Q4 -- "yes" --> O9["<b>Very many tenants, object-storage economics, per-tenant keys</b><br/>→ turbopuffer BYOC (author conflict disclosed; alternative: Zilliz BYOC)"]
  Q4 -- "no" --> Q5{"Vendor-hosted SaaS<br/>acceptable (non-<br/>confidential corpora)?"}
  Q5 -- "yes" --> O10["Any of the above in a UK/EU region; Weaviate if hybrid plus ISO 27001 managed service matters and the licence position is settled"]
  S5["<b>STEP 5 [Rec]: Checks before go-live</b><br/>• Leak test per tenant passes (zero)?<br/>• Filtered recall within tolerance?<br/>• Deletion canary within SLA?<br/>• Rebuild time inside exit-plan tolerance?<br/>• All copies (vectors, text, backups, caches) in approved regions?<br/>• Store recorded in the outsourcing / ICT register with an exit plan?"]:::note
  O11 ~~~ S5
```
