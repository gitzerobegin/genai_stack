# L2 decision tree: choosing a serving route and capacity model
Caption: Data class decides whether a router may be used, model availability in region decides between managed access and the other routes, GPU and SRE capacity decide between private-VPC managed inference and own GPUs, and demand shape decides reserved versus standard capacity before the go-live checks.

```mermaid
flowchart TD
  S0["STEP 0 [Rec] (not optional)<br/>Every route is called through the gateway (C1); the OpenAI-compatible API is the contract; each route records model, version, endpoint, processing region and retention setting; a fallback is qualified (L9) and in region."]

  S0 --> Q1{"STEP 1 [Rec]:<br/>What data will the<br/>route carry?"}
  Q1 -- "public / non-confidential only" --> PUB["Any approved managed API or router (OpenRouter, HF Inference Providers) with ZDR on; still through C1"]
  Q1 -- "client, personal or confidential data" --> Q2

  Q2{"STEP 2 [Rec]: Is the model you need available, processed in your approved region, on your primary cloud's model service?"}
  Q2 -- yes --> MAN["MANAGED ACCESS (default): Bedrock geographic/in-Region profile, Foundry Data Zone or Regional deployment, or Vertex regional/multi-region endpoint.<br/>Confirm who operates the model (hyperscaler vs partner)."]
  Q2 -- "no (model not in region, open-weight model needed, or exit route required)" --> Q2a{"Is the requirement<br/>an open-weight model?"}
  Q2a -- no --> VEN["Use the model vendor's own regional API only if contracted (DPA, ZDR, region) and registered as a material third party; otherwise choose a different model (L1)"]
  Q2a -- yes --> Q2b{"Do you have, or will you fund, GPU capacity AND an SRE team that can patch engines monthly and run on-call?"}
  Q2b -- no --> VPC["PRIVATE-VPC MANAGED INFERENCE: Fireworks BYOC or EU dedicated deployment (Strategic, conditional: once its ISO certificates are confirmed); Together EU dedicated endpoint (Scale/Enterprise, ZDR on); HF Inference Endpoints in an approved region with PrivateLink"]
  Q2b -- yes --> OWN["OWN GPUs: vLLM (supported distribution if your operating model needs a vendor), weights from an internal mirror; SGLang qualified as the backup engine (Strategic, conditional: once CVE-2026-3059 is confirmed fixed in the deployed version)"]
  OWN --> Q2c{"Multi-node, high volume,<br/>Kubernetes standard?"}
  Q2c -- yes --> LLMD["Pilot llm-d (CNCF) or Dynamo (NVIDIA estates) as the optimisation layer; non-production first"]
  Q2c -- no --> VLLM["vLLM alone"]

  PUB -- "go to STEP 3" --> Q3
  MAN -- "go to STEP 3" --> Q3
  Q3{"STEP 3 [Rec]: Capacity<br/>Is demand bursty but time-critical (month-end, quarter-end)?"}
  Q3 -- yes --> RES["Reserved / provisioned capacity sized for the peak (Foundry PTU, Vertex Provisioned Throughput with overflow pinned in region, Together PTU, Fireworks reserved), plus a qualified in-region fallback"]
  Q3 -- no --> STD["Standard / serverless in-region; batch APIs for non-interactive jobs"]

  RES --> S4
  STD --> S4
  S4["STEP 4 [Rec]: Checks before go-live<br/>• Processing region evidenced per call?<br/>• ZDR / retention confirmed in the contract, not just the console?<br/>• Fallback in the same region and qualified?<br/>• Engine version pinned and on the advisory watch list (self-hosted)?<br/>• Exit drill: route moved to the alternative by gateway configuration only?<br/>• Developer runtimes (Ollama, LM Studio): cloud disabled, no client data?"]
```
