# L1 decision tree: building a model portfolio by route, vendor and tier
Caption: Route every call through the gateway, let the data class decide which routes are allowed, pair a mid-tier primary with a fallback from a different vendor in the same region, add small, open-weight and frontier tiers only for their stated cases, and run the go-live checks.

```mermaid
flowchart TD
  classDef note fill:#FBF4E4,stroke:#D4A13A,stroke-dasharray:4 3;
  S0["STEP 0 [Rec] (not optional)<br/>All model calls go through the firm's gateway (C1) with pinned model IDs, data-class → route/region policy, logging to L9, and a model inventory entry (C8).<br/>Applications never call a vendor API directly."]

  S0 --> S1["STEP 1 [Rec]: Which routes may this data class use?"] --> Q1{"Client / personal /<br/>confidential data?"}
  Q1 -- yes --> A1["Only (a) hyperscaler-hosted, in an approved UK/EU region, in-tenant, no-training, ZDR or short retention; or (b) self-hosted open weights in the estate"]
  A1 -.- N1["Never: a vendor's own API without a first-party EU region and ZDR; any Chinese-origin vendor's own API; any 'trains on data' tier"]:::note
  Q1 -- "no (public or internal low-risk)" --> B1["Vendor API also allowed, after due diligence"]

  A1 --> S2
  B1 --> S2
  S2["STEP 2 [Rec]: Mid-tier primary and fallback<br/>(two different vendors, same region)"] --> Q2{"Primary cloud?"}
  Q2 -- Azure --> AZ["Primary: GPT-6.1 Sol (Foundry EU Data Zone)<br/>Fallback: Mistral Medium 3.5 (Foundry or EU endpoint)"]
  AZ -.- NAZ["EU processing for Claude on Foundry is not verified; its Azure-hosted deployment is still 'In-Process Q4 2026' for certification"]:::note
  Q2 -- AWS --> AW["Primary: Claude Sonnet 5.5 or GPT-6 tier on Bedrock in an EU region<br/>Fallback: the other of those two, or Mistral via Bedrock / EU endpoint"]
  AW -.- NAW["Confirm per-model regional availability; Astra is US-only on Bedrock"]:::note
  Q2 -- Google --> GO["Primary: Gemini 3.8 Flash (EU region, logging/caching off)<br/>Fallback: Claude Sonnet 5.5 via Google Cloud EU (GPT-6 is not on Google Cloud)<br/>Independent alternative: Mistral on Google Cloud (confirm model and region)"]
  Q2 -- "multi-cloud or none" --> MC["Primary: OpenAI EU endpoint (ZDR) or Mistral EU endpoint<br/>Fallback: the other; add a hyperscaler route when available"]
  NCL["Independent alternatives to any Claude choice (Anthropic Strategic, conditional, CP4-1): GPT-6.1 Sol, Gemini 3.8 Flash, Mistral Medium 3.5.<br/>Never Claude as the only qualified vendor."]:::note

  AZ --> NCL
  AW --> NCL
  GO --> NCL
  MC --> NCL
  NCL --> S3["STEP 3 [Rec]: Small and open-weight tiers"]

  S3 --> Q3a{"High-volume<br/>classification /<br/>extraction / routing?"}
  Q3a -- yes --> A3a["Small tier of the primary vendor (Luna, Haiku 5.5, Flash-Lite) or self-hosted Gemma 4"]
  S3 --> Q3b{"Data must never<br/>leave the estate, or<br/>air-gap required?"}
  Q3b -- yes --> A3b["Self-hosted: Gemma 4 (Apache 2.0), Mistral Medium 3.5 / Large 3, gpt-oss-120b<br/>→ Chinese-origin weights (DeepSeek MIT, Qwen3.8-27B, GLM-5.3-Flash) only if the firm's sovereignty policy explicitly allows them, never with tool access, and GLM only after sanctions review"]
  S3 --> Q3c{"Frontier tier<br/>(Astra, Fable 5.1,<br/>Argon)?"}
  Q3c --> A3c["Only when evaluation shows the mid tier fails a named use case; keep disabled otherwise"]

  A3a --> S4
  A3b --> S4
  A3c --> S4
  S4["STEP 4 [Rec]: Checks before go-live<br/>• Second vendor qualified on the same L9 suite? Failover drill passed?<br/>• Every pinned model's retirement date > re-qualification lead time?<br/>• Contract, DPA, register-of-information / MTP entry and exit plan done for each vendor?"]
```
