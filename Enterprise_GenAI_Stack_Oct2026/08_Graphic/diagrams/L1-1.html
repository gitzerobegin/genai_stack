L1 reference flow: one gateway routing calls across four model tiers
flowchart TD
  APP["Application / agent (L3)"]
  GW["Gateway C1<br/>Policy: data class → allowed routes and regions;<br/>task → model tier; pinned model IDs;<br/>fallback order; quotas; logging (L9, C6)"]
  APP -- "prompt + approved context<br/>(no raw client identifiers: C3)" --> GW
  GW --> FT["Frontier tier<br/>(gated, rare use)<br/>e.g. Astra / Fable"]
  GW --> MT["Mid tier (default)<br/>vendor A in-region<br/>e.g. GPT-6.1 Sol, Sonnet 5.5,<br/>Gemini 3.8 Flash, Mistral Medium 3.5"]
  GW --> ST["Small tier<br/>classification, routing, extraction<br/>e.g. Luna, Haiku 5.5,<br/>Flash-Lite, Ministral"]
  GW --> OW["Self-hosted open-weight tier (L2 serving)<br/>e.g. Gemma 4, Mistral Medium 3.5, gpt-oss<br/>(sensitive data stays in estate)"]
  MT -.-> FB["Fallback: vendor B, same tier, same region,<br/>qualified on the same L9 suite"]
  FT --> R
  MT --> R
  FB -.-> R
  ST --> R
  OW --> R
  R["Response"] --> G["Guardrails (C2)"] --> E["Evaluation (L9)"] --> I["Inventory and evidence (C8)"]
Every model call passes through the gateway (C1), which picks a tier and an approved route by data class and task, with a qualified same-tier fallback from a second vendor, before the response goes through guardrails, evaluation and evidence.
